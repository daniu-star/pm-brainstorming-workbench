# 03 · 评分卡（Rubric）

**版本**：V1.0。本文件是**唯一口径**。开轮前落盘到 `loop/rubric.md`，此后整轮运行期间**不得**修改权重、锚点与扣分系数。需要变更 → 开新版本号（见 §8）。

## 1. 使用规则

1. 八个维度各自打 **0–100 的整数**，不保留小数。
2. 总分 = Σ(维度分 × 权重) / 100，四舍五入到整数；**但门限判定用未取整的值**。
3. 每一维的分数必须能追溯到 `文件:行号` 或一条**可复跑**的命令；追溯不到的分数按"未评分"处理，不得用中间值填充。
4. 评测组独立打分；Lead 可复核、可要求补充证据，**不可抬分**。
5. 与自动化度量（proxy）不一致时，以人工判分为准，并在评分卡"口径说明"中并列两列。

### 1.1 权重

| 维度 | 名称 | 权重 |
|---|---|---:|
| A | 功能正确性与回归稳定性 | 20 |
| B | 服务端工程质量 | 15 |
| C | 前端与交互质量 | 15 |
| D | 安全与合规 | 15 |
| E | 产品逻辑与体验 | 15 |
| F | 测试与可验证性 | 10 |
| G | 文档与交付一致性 | 5 |
| H | 可运维性 | 5 |

### 1.2 计算示例

A=75, B=74, C=89, D=87, E=90, F=85, G=89, H=90 →

```
(75×20 + 74×15 + 89×15 + 87×15 + 90×15 + 85×10 + 89×5 + 90×5) / 100
= (1500 + 1110 + 1335 + 1305 + 1350 + 850 + 445 + 450) / 100
= 83.45 → 总分 83
```

## 2. 维度锚点

> 每维格式：定义 → 证据来源 → 100/85/70/50 四档锚点 → 扣分锚点 → 本维常见误判。
> **打分方法**：先按四档锚点找到**最接近的档**，再按扣分锚点在本档基础上调整，最后夹到 0–100。

### A · 功能正确性与回归稳定性（20）

**定义**：核心链路在**可重复执行**的条件下是否稳定正确。
**证据来源**：pytest 全量结果（含 skipped 明细）、同一命令重复两次的差异、order-dependence 实验（单跑/组合/并行/串行近全量）、关键链路 API 冒烟。

| 分 | 锚点 |
|---:|---|
| 100 | pytest 全绿（0 failed / 0 error）；同一命令连跑两次结果完全一致；无顺序依赖用例；关键链路 API 冒烟 100% 通过 |
| 85 | 全绿但存在已文档化的 flaky；或有 1 个"本该测却没测"的 skip（有明确补测计划） |
| 70 | 1 个稳定失败；或 2 个顺序依赖用例 |
| 50 | ≥3 个失败；或核心链路（采集 / 发布前准备 / 日历）任一段不可用 |

**扣分锚点**：每个稳定失败 −8；每个顺序依赖用例 −4；每缺一条契约断言 −2。

**常见误判**：把"单文件跑绿"当全绿；把"并行跑绿"当无顺序依赖（并行常常掩盖共享状态）；把 `skipped` 计为通过。

### B · 服务端工程质量（15）

**定义**：异常、事务、并发、分层、规模五项是否达到可维护水平。
**证据来源**：代码审计（`except` 分支、事务边界、子进程生命周期、路由层是否写 SQL、单文件行数）、错误码是否可区分。

| 分 | 锚点 |
|---:|---|
| 100 | 关键路径无裸 `except`；写操作有事务/幂等；子进程有生命周期管理与回收；路由与服务分层清晰；单文件 ≤800 行；错误码可区分 |
| 85 | 少量宽泛异常，均位于非关键路径且有上下文日志 |
| 70 | 关键路径吞异常；或"失败就换设备/换客户端"式的状态重置；或存在 >1500 行的文件 |
| 50 | 缺事务导致可复现的数据不一致；或存在资源泄漏（进程/句柄/连接） |

**扣分锚点**：每个关键路径吞异常 −3；每处无上下文的 `except Exception: pass` −2；存在 >1500 行文件 −3；路由层每条 SQL −2。

**常见误判**：只看异常数量不看位置（非关键路径的宽泛异常不该重罚）；把"顺手重构"计入 B 维加分（重构本身不加分，等价性证据才加）。

### C · 前端与交互质量（15）

**定义**：外部文本是否安全渲染、异步视图是否三态完备、关键操作是否可达、首屏是否可用。
**证据来源**：静态扫描（`innerHTML`、字符串拼接转义）+ 浏览器实测（console error、三态截图、键盘操作、首屏时延）。

| 分 | 锚点 |
|---:|---|
| 100 | 所有外部文本经转义后进入 DOM；每个异步视图有 loading/empty/error 三态；关键控件有 label/aria 且键盘可达；首屏可交互 <2s；console 无 error |
| 85 | 三态基本完整，少数列表缺空态文案 |
| 70 | 存在未转义的 `innerHTML` 拼接（外部输入可达，构成 XSS 面）；或有视图只有 loading 没有 error |
| 50 | 接口失败后界面永久 loading 且无任何反馈 |

**扣分锚点**：每处外部输入可达的未转义拼接 −4；每视图缺 error 态 −3；每视图缺 empty 态 −1；主要操作不可键盘触达 −2。

**常见误判**：把 `innerHTML` 的出现次数当风险数（赋值 vs 读取不同）；忽略"失败被渲染成空列表"——那是把故障伪装成没有数据，比报错更糟。

### D · 安全与合规（15）

**定义**：凭据、访问控制、外部内容隔离、生成内容标识、日志脱敏五道面。
**证据来源**：磁盘与代码扫描（明文凭据、argv 传参）、访问控制清单与实际写接口的动态枚举比对、模型入口的不可信内容包裹、标识落盘与像素取证、异常路径脱敏。

| 分 | 锚点 |
|---:|---|
| 100 | 凭据不落明文、不经 argv；所有敏感接口在访问控制清单内（且默认拒绝）；外部文本在进入模型前被包裹为不可信内容；生成内容有显式标识 + 元数据；日志脱敏覆盖异常路径 |
| 85 | 存在 1 处单点绕过（例如某条日志里出现凭据字段名） |
| 70 | 明文 cookie/key 落盘；或敏感接口漏在访问控制清单外 |
| 50 | 命令/参数注入、路径穿越、未鉴权的破坏性接口 |

**扣分锚点**：每处明文凭据落盘 −6；凭据经 argv 传递 −4；每个未覆盖的敏感接口 −3；每处未脱敏日志点 −2；缺失生成内容标识 −5。

**常见误判**：把"字段名出现在报告里"当泄漏（报告只写字段名与位置是正确做法）；把"沙盒里通过"当真实可用；把历史遗留的凭据文件算作代码缺陷（它是**运维动作**，需单列并写清处置责任）。

### E · 产品逻辑与体验（15）

**定义**：主干链路是否闭环、文案是否诚实、断点是否有出路、指标定义是否唯一。
**证据来源**：主流程逐步走查（7 步：选题 → 素材 → 生成 → 审核 → 排期 → 发布 → 复盘）、文案与代码行为对照、断点场景实测、指标口径检索。

| 分 | 锚点 |
|---:|---|
| 100 | 主链路 7 步每步都有完成判据与下一步入口；断点有兜底或逃生路径；文案不承诺做不到的事（不把排名分数说成效果预测）；空态给出可执行引导；同一指标全站一个定义 |
| 85 | 链路闭环，但个别步骤缺"下一步" |
| 70 | 存在假成功（界面显示完成、实际未执行）；或指标定义不一致 |
| 50 | 主流程断裂（无法从选题走到发布） |

**扣分锚点**：每处假成功/静默降级 −5；每处定义不一致 −3；每个无引导断点 −2；每处夸大承诺 −3。

**常见误判**：把"有按钮"当"有出路"（按钮点了报错、或能力未接上，等于更深的死路）；把"文档写了"当"用户可达"。

### F · 测试与可验证性（10）

**定义**：测试是否可信、是否隔离、是否覆盖契约、能否并行、CI 是否真的跑过。
**证据来源**：覆盖率或核心模块有无测试、网络/真实站点依赖、skip 明细、并行稳定性、CI 运行记录、套件时长。

| 分 | 锚点 |
|---:|---|
| 100 | 核心服务有直接测试；关键契约（错误码/schema/幂等）有断言；测试不依赖网络与真实站点；可并行；CI 存在且**跑过**；套件 <5min |
| 85 | 覆盖可接受，套件 5–10min |
| 70 | 核心模块无测试；或测试依赖真实外部服务 |
| 50 | "skip 即通过"；或长期 skip 掩盖缺口 |

**扣分锚点**：每个零测试的核心模块 −3；每个永久 skip −2；套件 >10min −3；无 CI −2。

**常见误判**：把"CI 配置文件存在"当"CI 跑过"；把"并行绿"当稳定（UI 类测试在并行下常假绿）；把测试数量当覆盖质量。

### G · 文档与交付一致性（5）

**定义**：文档描述的能力是否都有代码对应，数字是否与事实一致，限制是否写明。
**证据来源**：README/PRD/运维卡逐条与代码比对（能力、路由数、测试数、表数）、限制章节是否存在。

| 分 | 锚点 |
|---:|---|
| 100 | 文档描述的每个能力都有代码对应；各类数字与事实一致；失败与限制显式写明 |
| 85 | 存在 1–2 处表述模糊但不误导 |
| 70 | ≥3 处"文档说有、代码没有" |
| 50 | 核心能力描述为假 |

**扣分锚点**：每处虚假声明 −2。

**常见误判**：只核对"文档里有没有这一节"；忽略过期的数字（"11 个视图"实际 10 个，这类小谎言累积起来会摧毁文档可信度）。

### H · 可运维性（5）

**定义**：能否安全启动、能否诊断、健康检查是否诚实、迁移是否可重放。
**证据来源**：启动前检查、`/api/health` 与 `/ready` 的输出、日志关联 id、迁移重复执行、失败退出码。

| 分 | 锚点 |
|---:|---|
| 100 | 启动前有前置检查；`/api/health` 区分存活/就绪并给出 `blocking_reasons`；日志带关联 id；迁移可重复执行；失败退出码正确 |
| 85 | 小缺口（例如缺关联 id） |
| 70 | 健康检查只返回 200 不含状态；或迁移不可重复执行 |
| 50 | 启动即静默降级为不可用状态且无法诊断 |

**扣分锚点**：健康检查撒谎 −3；迁移不可重复 −3。

**常见误判**：把"有 health 接口"当"健康检查诚实"（永远 200 的 health 比没有更危险）；把"写了 doctor 脚本"当"启动会拦截"。

## 3. 严重性分级与封顶

| 级别 | 定义 | 处理 |
|---|---|---|
| **P0** | 数据损坏 / 安全泄漏 / 主链路不可用 / 假成功 | 必须在本次 Loop 内修复，**否则总分封顶 89** |
| **P1** | 用户可感知的关键路径体验或可靠性缺陷 | 本轮修复，或给出书面豁免理由 |
| **P2** | 局部质量（可维护性/一致性/性能） | 尽力修复，可挂账到下一轮 |
| **P3** | 打磨项 | 可长期挂账 |

封顶规则只在"评测组确认 P0 仍存在"时生效；"已缓解""部分修复"不算关闭。P0 的关闭判据必须是**可复跑的证据**（例如：伪造 Host 头返回 421、删除断言前的红/绿记录、像素取证显示标识存在）。

## 4. 硬闸门

全部满足才 `PASS`：

| # | 条件 | 说明 |
|---|---|---|
| 1 | 总分 ≥ 95 | 用未取整值判定 |
| 2 | A ≥ 95 | 等价于 pytest 全绿 |
| 3 | D ≥ 90 | 安全与合规不可用总分换 |
| 4 | 无未关闭 P0 | 逐条列出关闭证据 |
| 5 | 评测组独立复核并签字 | 签字人不得是任何修复的作者 |

任一不满足 → `FAIL`，进入下一轮，**最多 5 轮**。满 5 轮仍未达标 → 如实报告当前分数、未关闭项、根因假设与下一步，**不四舍五入、不口头拔高、不改写为"基本达标"**。

## 5. 反作弊条款

以下行为一旦被确认，按最重档处理：

1. **删除/跳过/弱化断言以换取绿灯** → 该轮 **A 维记 0**。
2. **只改文档"消除"问题**（代码不变、文档改口径） → 该维度按原缺陷计分，且 G 维额外扣分。
3. **把"沙盒通过/模拟通过"写成"真实可用"** → 按假成功计（P0），总分封顶 89。
4. **开发者给自己打分或施压评测组抬分** → 该轮评分作废，重评。
5. **口径漂移**（同一指标换算法使分数上升而不声明） → 该轮该维分数作废，按统一口径重算。

## 6. 评分卡必须回答的问题

一张合格的评分卡，读者应能在**不读代码**的情况下回答：

1. 每个维度为什么是这个分？（一句话锚点理由 + 证据位置）
2. 上轮的差距项这轮关了吗？关的证据是什么？
3. 有没有"声称成立但实际不成立"的说法？（列出被推翻的声明）
4. 闸门逐条过了吗？没过的那条差多少？
5. 历史分数与本次口径一致吗？不一致在哪、要不要回算？

## 7. 与自动化度量的关系

`scripts/measure_repo.py` 产出的 `proxy` 分**只是输入锚点**，不是维度分。

- proxy 偏低而人工判分偏高：说明度量口径过严或有误报，需在评分卡说明。
- proxy 偏高而人工判分偏低：**最常见**，说明度量只看了"有没有"，没看"是否有效"。真实案例里 proxy 给 93.9，评测组给 83。

规则：不一致时**并列两列**，不改度量规则凑分；需要新口径时作为**新增字段**另报。

## 8. 变更规则

- 改权重、改锚点、改扣分系数、改闸门阈值 → 必须开新版本号（V1.1 / V2.0），并写进 `CHANGELOG.md`。
- 发布说明必须写明：**新版本与历史轮次分数不可直接比较**。
- 绝不允许为了某个项目当期达标而临时改权重或锚点。这条一旦破了，评分卡就退化为自我安慰。
