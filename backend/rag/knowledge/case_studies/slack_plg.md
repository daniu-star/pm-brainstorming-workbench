# Slack 的产品驱动增长（PLG）

## 背景

Slack 最初是一个游戏公司（Tiny Speck）的内部沟通工具。游戏 Glitch 失败后，团队发现他们的内部沟通工具比游戏本身更有价值。2013 年转向企业协作，2019 年上市。

## 核心增长引擎：自下而上的 PLG

传统企业软件销售路径：销售 → 采购 → IT → 员工被迫使用
Slack 的路径：员工自发使用 → 团队扩散 → 部门采纳 → 企业购买

这个路径的关键是**端用户价值必须足够强**，强到员工愿意在没有公司指令的情况下主动使用。

## 关键产品决策

1. **免费增值（Freemium）模型**：无限用户、有限历史消息。团队可以无限期免费使用，这是自下而上渗透的燃料
2. **魔法时刻**：用户发第一条消息后立即看到价值。没有培训、没有上手引导、没有强制教程
3. **集成生态**：Slack 本身不是工具，是工具的"连接器"。与 Google Drive、GitHub、Jira 等深度集成，让信息在工具间流动
4. **品牌语调**：Slackbot 的友好文案、加载页的趣味提示、出错页的幽默——让企业软件"有人味"

## 为什么 Slack 赢了（当时）

- Email 的协作效率太低（邮件链、附件、抄送混乱）
- HipChat 体验粗糙、不稳定
- Microsoft Teams 当时还不存在
- 时机：远程办公趋势刚起步，分布式团队需要异步沟通工具

## 产品启示

1. **PLG 的核心不是"免费"，是"端用户真爱用"**。如果免费用户不是因为产品好而留下，PLG 就没有意义
2. **企业软件也可以有好体验**。Slack 证明了"好用"本身就是企业软件的竞争壁垒
3. **集成 > 全家桶**。Slack 没有试图做文件存储、项目管理、代码托管——它选择成为这些工具的"中央神经系统"

## 面试中可引用的观点

- "产品的魔法时刻是什么？用户在第几分钟能感受到核心价值？"
- "如果做 B2B 产品，你的增长路径是自上而下（销售驱动）还是自下而上（产品驱动）？为什么？"
