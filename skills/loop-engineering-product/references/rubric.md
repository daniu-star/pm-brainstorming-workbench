# 评分卡与硬上限裁定（Loop Engineering Product v1.0）

## 总分构成（100）

| # | 维度 | 满分 | 核心问题 |
|---|---|---|---|
| 1 | 产品与需求达成 | 20 | 需求真的闭环了吗？用户能不能把事做完？ |
| 2 | 功能正确性 | 15 | 主路径/边界/异常路径行为对不对？ |
| 3 | 数据一致性与状态机 | 15 | 崩溃、并发、重放后数据还对不对？ |
| 4 | 交互与前端逻辑 | 15 | 前端能否从服务端真相重建，且不卡死？ |
| 5 | 架构与代码质量 | 10 | 六个月后还能改吗？ |
| 6 | 安全与错误处理 | 10 | 越权/泄漏/错误码语义守得住吗？ |
| 7 | 自动化测试与证据 | 10 | 关键行为有真实用例守护吗？ |
| 8 | 文档与可运维 | 5 | 新人能在干净机器上跑起来吗？ |

## 分锚点（每维通用）

| 分档 | 含义 |
|---|---|
| 95–100 | 生产级：关键路径有守护，异常可恢复，文档可复现，几乎无已知未闭合项 |
| 85–94 | 可发布：主流程稳，存在少量 P2 与已知边界，不影响核心用户 |
| 70–84 | 可演示：主流程能走通，但存在 P1 或明显状态缺口 |
| 60–69 | 半成品：关键路径有 P0 或数据一致性缺口 |
| 0–59 | 不可用：主流程断裂或不可验证 |

## 硬上限裁定流程

评测组每轮打分**之后**执行：

```
openP0 = findings 中 severity=P0 且本轮未被修复验证通过的数量
openP1 = findings 中 severity=P1 且本轮未被修复验证通过的数量
weakened = 是否出现删用例/改期望值/skip/恒真断言

total = min(total, 100)
if openP0 >= 1:        total = min(total, 70)
if openP1 >= 3:        total = min(total, 85)
if weakened:           total = min(total, 60)   # 且要求回退
```

判定「已修复」必须同时满足：
1. 修复角色给出 `filesChanged` + 改动说明；
2. 测试组复测真跑通过（含新增/既有用例）；
3. 评测组抽查代码确认不是「绕过问题」（例如注释掉异常路径）。

## 分维扣分口令（写进 reason）

- 产品：`主流程在第 N 步断开`、`AC-x 声称覆盖但无对应用例`、`入口不可发现`。
- 功能：`输入 X 返回 Y（应 Z）`、`边界 N+1 未处理`。
- 数据：`崩溃点在事件写入前`、`重放导致重复应用`、`版本可回退`。
- 交互：`过期响应覆盖新状态`、`错误后无法重试`、`切页残留订阅`。
- 架构：`同一契约两处定义`、`业务逻辑散落在路由层`。
- 安全：`owner 校验缺失`、`软删后仍可读`、`错误码把 401 写成 500`。
- 测试：`零用例覆盖关键路径`、`用例只断言字符串存在`。
- 文档：`命令跑不通`、`缺回滚说明`、`已知边界未记录`。

## 收敛判据

- `total >= target` 且无未修 P0 → 交付，输出 release verdict。
- 轮次耗尽仍 < target → 输出「未闭合项清单（含最小下一步）+ 建议不发布/限定范围发布」。
- 分数连续两轮不升 → 要求下一轮**只做一件事**：消灭最高 ROI 的单点缺陷，禁止全面铺开。
