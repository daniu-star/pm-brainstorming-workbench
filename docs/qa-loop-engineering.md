# QA Loop Engineering（产品研发闭环）

> 面向 PM Brainstorming Workbench 的多角色评测闭环：**规划 → 研发 → 测试 → 迭代 → 评测**，
> 每轮由 5 个独立小组并行取证，评测组按 100 分制打分决定是否收敛。

## 1. 目标与退出条件

| 项 | 值 |
| --- | --- |
| 最大轮次 | 5 |
| 收敛阈值 | 评测总分 ≥ 95 |
| 轮次结构 | 审计（4 组并行）→ 评分（评测组）→ 修复（客户端 + 服务端并行）→ 复测（测试组） |
| 产物 | 每轮打分卡、修复清单、真实测试数字、最终验收结论 |

收敛即停止，不再为"刷分"追加轮次；未达阈值跑满 5 轮也必须交卷，并在报告中标注未闭合项。

## 2. 角色编制

| 组 | 职责 | 写权限 |
| --- | --- | --- |
| 产品组 | 主流程可走通性、FR/AC 一致性、入口与状态可见性、空态/加载/失败恢复 | 只读 |
| 客户端开发组 | 前端逻辑正确性：竞态、丢更新、去重、SSE 解析、版本单调、审计页与画布状态 | 只读（审计）/ `frontend/**`（修复） |
| 服务端开发组 | 幂等、状态机、租约、预算、审计幂等、越权与软删、事务边界、错误码语义 | 只读（审计）/ `backend/**`（修复） |
| 测试组 | 真跑三套验证（后端 496 / 前端 87 + tsc / e2e），覆盖缺口与 flake，提出新用例 | 只读 |
| 评测组 | 独立交叉验证 + 7 维打分 + 输出按优先级修复清单 | 只读 |
| 发布/运维（补充） | 一键启动、健康诊断、迁移演练、CI 可用性（体现在第 7 维，不单独成组以免空转） | — |

> 说明：用户给的角色分类里没有独立的"发布/运维"组，这里把它并入评测维度 7；
> 也没有独立"架构组"，架构问题由服务端/客户端组在各自审计里提出，避免空转角色。

## 3. 每轮流程

```
审计(并行4) ─→ 评分(评测组) ─→ [>=95 收敛] ─→ 修复(客户端+服务端并行) ─→ 复测(测试组) ─→ 下一轮
```

- **审计**：四组各产出 ≤10 条发现，必须带 `文件:行号` 证据、用户影响、修法、验证方式。
- **评分**：评测组必须先自证（真跑至少一条验证命令），再按 7 维打分；无证据不得满分。
- **修复**：只按评测组清单动手，客户端只改 `frontend/**`、服务端只改 `backend/**`，最小改动、不得削弱测试、不得新增依赖。
- **复测**：真跑后端全量 + 前端类型/单测（时间允许再跑 e2e），与上一轮对比是否回归。

## 4. 评分卡（满分 100）

| 维度 | 分值 | 满分要求 |
| --- | --- | --- |
| 功能正确性 | 25 | 主流程（澄清→确认→四角色→画布→审计→报告）行为符合 PRD，且有测试证据 |
| 数据一致性与状态机 | 20 | 幂等、版本、租约、单一终结事件、取消优先、事务原子性均有断言 |
| 错误处理与边界 | 15 | 错误码语义、超时、预算、越界输入、软删与越权均有测试 |
| 前端逻辑与交互 | 15 | 无丢更新/重复提交/竞态，加载与失败可恢复 |
| 架构与代码质量 | 10 | 分层清晰、无死代码/旧写路径、契约单一真相源 |
| 自动化测试 | 10 | 覆盖度、真实性（跨进程/端到端）、稳定性 |
| 文档与可运维 | 5 | README / 验收报告 / 发布清单 / 一键启动 / 健康诊断可用 |

硬规则：

- 存在未修的 **P0** → 总分上限 70；
- 存在 ≥3 条 **P1** → 总分上限 85；
- 测试"变绿"只能来自实现修复，不能改期望值、删用例、跳过断言。

## 5. 证据纪律

1. 所有数字必须来自真实命令输出（`Ran N tests` / `pass N` / `exit 0`），不得推演。
2. 每条发现必须能定位到具体文件与行号；修复必须说明"改了什么 / 验证命令 / 结果"。
3. 跨进程/并发类结论必须有真进程或独立 DB 连接证据，不接受"看起来对"。
4. 环境限制要如实记录：npm registry 不可达 → 前端用 `node --test` 而非 vitest；8000/3000 被其他程序占用 → 端口 8001/3001。

## 6. 复用方式

闭环脚本见 [scripts/qa-loop.workflow.js](scripts/qa-loop.workflow.js)（由 DSH workflow 工具加载执行，脚本本身不落盘运行）。
每轮结果建议归档到 `docs/qa-loop-runs/round-<N>.md`，字段固定为：轮次、总分、各维度、P0/P1 数、修复清单、测试数字、结论。
